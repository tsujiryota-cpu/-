# 🏆 みんなのランキング(全作品共通)

スコアの出る6作品(しげる軍団 / しげる大乱闘 / CRしげさん / しげる叩き / しげるのおにぎり / しげる決闘)に共通のランキング。

- 結果画面の「🏆 スコアを登録してランキングを見る」からニックネーム(12文字まで)を入れて登録
- ニックネームは端末に記憶され、次回以降は自動で入る
- ポータル(`games/index.html`)の「🏆 みんなのランキングを見る」で**全6作品をタブ切替**で閲覧(上位20位)
- スコアには付随情報も残る(曲名/難易度、連鎖数、撃破数、人抜き数とCPUの強さなど)
- 実装は `ranking_snippet.js` を各ゲームにビルド時注入する共通モジュール

## 保存先の仕組み

共有ストアは**1つのJSONドキュメントに全ゲーム分**を入れる方式。

```json
{ "onigiri": [...], "tataki": [...], "puyoshige": [...], "duel": [...], "smash": [...], "gundan": [...] }
```

GETとPUTだけで動くので、認証なしで読み書きできる先ならどこでも使える
(jsonblob / Firebase Realtime Database など)。各 `build_*.py` の `RANK_ENDPOINTS` に書く。

- **保存先は複数指定できる**。GETは繋がった先から読み、PUTは**全部に書く**(二重化)
- 通信失敗時は自動で端末内モードにフォールバックするのでゲームは壊れない

## 「1日経つと消える」への対策

jsonblobの匿名Blobには**24時間の有効期限**がある。これで記録が消えていたので、
消えないようにするのではなく**消えても復活する**作りにした。

1. **端末内に全ゲーム分の控えを持つ**(`localStorage: shige_rank_all`)。
   共有側が空になっても手元の記録は残る
2. **自己修復** — 誰かがランキング画面を開いたとき、共有側が端末内の控えより少なければ
   **その場で自動的に書き戻す**。つまり誰か1人が開けば全体が復活する
3. **ランキング画面の「⚙️ 保存先とバックアップ」** から:
   - 恒久的な保存先URLを**この端末だけに設定**できる(再ビルド不要。`shige_rank_ep`)
   - 記録を**バックアップとしてコピー**でき、貼り付けて**復元**もできる
     (復元すると共有側にも書き戻す)
4. jsonblobに繋がっている間は**画面に警告を出す**(24時間で消えることと、対処法)

## 恒久的な保存先にする手順(Firebase Realtime Database)

無料で、期限なしで、サーバのコードを書かずに使える。

1. https://console.firebase.google.com/ でプロジェクトを作る
2. 左メニューの **Realtime Database** → 「データベースを作成」→ ロケーションは任意 →
   **「テストモードで開始」**
3. **「ルール」タブ**を開いて次に書き換えて公開する(テストモードのままだと30日で読み書きできなくなる)
   ```json
   { "rules": { ".read": true, ".write": true } }
   ```
4. 「データ」タブに出ている `https://xxxx-default-rtdb.firebaseio.com/` の末尾に
   `shige.json` を付けたURLを、ランキング画面の「⚙️ 保存先とバックアップ」に入れて「保存先を設定」
5. 動いたらそのURLを各 `build_*.py` の `RANK_ENDPOINTS` の**先頭**に足して再ビルドすると、
   全員の端末で恒久的な保存先が使われる

ルールを公開にするので、URLを知っている人は誰でも書き換えられる。身内で遊ぶ前提の割り切り
(だからこそ端末内の控えと自己修復を入れてある)。

# 📱 iPhoneで「勝手に画面が拡大されて戻せない」対策(全作品共通)

連打していると画面が拡大され、そのまま縮小できなくなる問題への対策(`nozoom_snippet.html` を全ページに注入)。
Safari でも Chrome でも起きる(iOSのChromeは中身がWebKitなので同じ挙動になる)。

## 疑わしい経路は2つある

**(A) ブラウザのページ拡大**

iOS は `user-scalable=no` と `maximum-scale` を**無視する**(アクセシビリティのため)。そのうえで
連打が「ダブルタップ拡大」と、別々の指でボタンを押すのが「ピンチ」と誤認される。
`maximum-scale=1` を指定していると**縮小して戻すこともできず詰む**。

**(B) ゲーム内カメラの寄り(しげる大乱闘のみ)**

2人が密着すると自動でカメラが寄る。上限が2.3倍と強すぎたため、殴り合っている間ずっと
拡大されたままに見えていた可能性がある。**上限を1.55倍に下げ**、強打時のズームパンチも
0.30→0.16、減衰を .82→.76 に変えて素早く戻るようにした。

タイトル画面の下に**現在の表示倍率をリアルタイムで出す**ようにしたので、
拡大された状態でここが 1.00 のままなら (B)、1.00 より大きければ (A) と切り分けられる。

## (A)への対策(二段構え)

**① 拡大させない**

- `*, *::before, *::after { touch-action: manipulation }` — **全要素に個別指定**
  (祖先まかせだと iOS が拾わない)
- 各ゲームの「指で直接さわる面」と**その中の子要素すべて**を `touch-action: none` に。
  ここが最初の版の穴だった: `<button>A<small>攻撃</small></button>` のラベル部分を叩くと
  判定対象が `<small>` になり、面にしか指定していなかったので素通りしていた
  (スティックのつまみ `#knob` も同様)
- **操作面のタップは常に `touchend` で `preventDefault`**。当初は「330ms以内かつ44px以内の
  2発目だけ潰す」としていたが、大きいボタンを連打すると指の位置が44pxを超えてすり抜ける。
  間隔も位置も当てにならないので、面ごと潰す方式に変えた
- 潰す対象かどうかは **e.target から祖先を10段まで遡って**判定する。途中に `onclick` を持つ
  要素や `<a>/<input>/<label>` があれば対象外にするので、**clickで動くメニューのボタンは
  一切潰さない**(start/pause/resume/home など全ボタンで検証済み)
- ピンチは Safari独自の `gesturestart/change/end`、`touchmove` の `e.scale !== 1`、
  操作面で2本目の指が触れた瞬間の `touchstart` の3箇所で止める。
  pointerイベントは先に発火済みなので、スティック+ボタンの同時押しは壊れない
- **決闘の手札(`.card`)は除外** — 横スワイプでスクロールする必要があるため `pan-x` のまま

**② それでも拡大されたら必ず戻せる**

- `maximum-scale` と `user-scalable=no` を**やめた**。固定すると詰むので、
  最後の手段としてピンチで縮小できる状態を残しておく
- `visualViewport.scale > 1.02` を検知したら自動で倍率を1に戻す
  (現在の倍率より小さい `maximum-scale` を一瞬はさむと切り詰められる。0.7秒に1回のスロットル)
- 自動復帰が4回失敗したら**「🔍 表示を戻す (1.85倍)」ボタン**を出す。
  `visualViewport` のオフセットに追従して**常に可視領域の左上に貼り付く**ので、
  どれだけ拡大されていても必ず押せる
- 画面復帰時(`visibilitychange`)と画面回転時にも復帰処理を実行

**③ キャッシュ対策**

配信ファイルは14〜29MBあり、Safariに古い版が居座りやすい。

- ゲームセンターのポータルから各ゲームへのリンクに `?v=<ビルド時刻>` を付けて、
  ビルドするたびにURLが変わるようにした
- 大乱闘のタイトルに `build 2026.08.15-<月日-時分>` を表示。古い版を掴んでいないか確認できる
- それでも古い版が出る場合はプライベートタブで開くのが確実

- 縦に長い読み物(ゲームセンターのポータル / 颯思颯愛診断)は、読みやすさのため
  **ピンチ拡大は残したまま**ダブルタップ拡大だけ止めている
- 複数指の同時操作を使う作品(大乱闘のスティック+ボタン、酒場の指ルーレット)があるので、
  「2本指のタッチを一律に潰す」方式は採っていない

# 💥 しげる大乱闘【スマブラ風対戦格闘・科学的根拠0人】

`smash/index.html`。これまでの全素材から**10キャラ**を仕立てた、ふっとばし合いの対戦格闘。
%が溜まるほど遠くへ飛び、画面外(ブラストライン)に叩き出すと1ストック奪える。

## モード

| モード | 内容 |
|---|---|
| ⚔️ 1人で対戦 | 好きなキャラでCPUと3ストック勝負(2分) |
| 🏆 乱闘ロード | **10人抜き**。相手は2ストック、戦うごとに強くなり、最終戦は**自分の分身**。スコアはみんなのランキングへ |
| 👥 2人で対戦 | スマホ1台を横に置いて、左右に分かれた操作パッドで2人同時対戦 |

## CPUの強さ(5段階)

キャラ選択画面で選ぶ。選択は端末に保存され、次回も引き継がれる(`localStorage: smash_cpu_lv`)。

| | 判断間隔 | 攻めっ気 | スマッシュ溜め | 崖狩り | 棒立ち | 読み | 復帰の遅れ | 中身 |
|---|---|---|---|---|---|---|---|---|
| **雑魚** | 42〜84F | .30 | 10F | 0 | 42% | .15 | 26F | 棒立ちが多い。歩いてきて弱攻撃を振るだけ |
| **弱い** | 30〜62F | .52 | 20F | 8% | 22% | .35 | 14F | たまにスマッシュ。復帰はしてくる |
| **ふつう** | 22〜46F | .70 | 30F | 24% | 10% | .60 | 6F | 空中攻撃と必殺を混ぜてくる。ガードもする |
| **強い** | 15〜33F | .86 | 40F | 48% | 3% | .82 | 2F | 溜めスマッシュと崖狩り。隙を見逃さない |
| **激強** | 9〜22F | .96 | 50F | 72% | 0% | 1.0 | 0F | 反応がほぼ即時。崖外まで追ってきて叩き落とす |

- **崖狩り**は、相手が場外にいるとき自分も崖の外まで出て空中攻撃で叩き落としにいく行動。強いCPUほど深く追う(自分が落ちそうになると中断する)
- **読み**は、飛び道具をガード/ジャンプで避ける精度と、相手のスマッシュ溜めにカウンター・ガードで割り込む精度
- **復帰の遅れ**は、崖外に出てから復帰行動を始めるまでの間。雑魚は反応が遅れて、そのまま落ちることがある
- 同キャラ・同条件で150秒戦わせた実測: **激強 vs 雑魚 の与ダメージは 257% 対 49%**、撃墜され数は雑魚10回・激強5回
  (ふつう vs 雑魚 なら 112% 対 28%)
- 乱闘ロードは選んだ強さを**基準**にして1戦ごとに上がる(ふつう→ `1,2,2,3,3,4,4,5,5,5` / 激強→ `3,4,4,5,5,5,5,5,5,5`)
- ロードのスコアは難易度倍率がかかる(雑魚0.55倍 〜 激強1.65倍)

## ふっとばしの計算

```
ふっとび速度 = (基礎 + 成長 × (相手の% + 技のダメージ×0.8) / 11) ÷ 相手の重さ
```

同じ横スマッシュでも 0%:9.0 → 60%:14.3 → 140%:21.3 と伸び、軽い相手(syamu)は重い相手(野獣先輩)の約1.6倍飛ぶ。

## 操作系が「押されたまま」固まらないようにする

スティックが一方向に固定されて操作不能になる不具合があった。原因は指を離したイベントの取りこぼし。

- `pointerup` を `#stick-zone` の上でしか拾っていなかった。結果画面のオーバーレイが出た瞬間などに
  イベントが別の要素へ飛ぶと、最後の傾き(`input.lx/ly`)が残り続けてキャラが走り続ける
- さらに `if (id !== null) return;` のせいで**新しい指で掴み直すこともできず**、完全に詰んでいた

4段構えで直した(どれか1つでも効けば復帰する)。

1. `setPointerCapture` で、指がゾーンの外に出ても同じ要素にイベントが届くようにする
2. `pointerup` / `pointercancel` を **window の capture フェーズでも**拾う。
   `lostpointercapture` も離す合図に使う
3. **画面上の指が0本になったら全部離す** — `touchend`/`touchcancel` の
   `e.touches.length === 0` を見る。これが最後の砦で、`pointerup` が完全に消えても効く
4. **0.16秒ごとの見張り** — 生きているポインタの集合を持っておき、掴んでいるIDが
   消えていたら強制的に離す
5. 掴んでいる指が行方不明でも、**新しい指で必ず乗っ取れる**ようにした(固まったままにしない)
6. 試合開始時・ポーズ時・タブが非表示になった時・ウィンドウがblurした時も全解除

同じ処理をボタン(A/B/J/G)にも入れた。ボタンが押されたままになると、
Aが押しっぱなしでスマッシュを溜め続けるなどの症状になるため。

検証: 「ゾーン外で離す」「upが完全に消える」「見張りでの復帰」「固まった状態から乗っ取る」
「試合が切り替わっても持ち越さない」「離した後に歩き出さない」を14項目で確認。

## 音

## 🎯 さらにカスタマイズする方法

`index.html` の `<script>` 冒頭にある **「★ 身内ネタカスタマイズゾーン ★」** を書き換えるだけです。

### 質問を変える

```js
{ axis: 0, text: "○○(友達の名前)がまたアレをやらかした。あなたは?", choices: [
  ["一緒にやらかす", 1],       // +1 = 前者(B/D/S/C)寄り
  ["写真だけ撮る", 0],          //  0 = どっちつかず
  ["先に帰国する", -1],         // -1 = 後者(W/I/K/J)寄り
]},
```

- `axis` は 0〜3(上の表の順)
- 各軸の質問数は自由に増減OK(バーの%計算は「1軸3問」前提なので、変えるなら `showResult` 内の `+ 3) / 6` をその軸の質問数に合わせて調整)

### 診断結果を変える

```js
WDSC: { name: "syamu",                    // タイプ名 → 身内のあだ名にすると最高
  tagline: "文句を言うならお前が作れ",     // 一言キャッチコピー
  desc: "どんな人かの説明",
  manual: "取扱説明書(この人との付き合い方)",
  neta: "元ネタ解説(にわか向け)",
  best: "BIKC",   // 相性◎のタイプコード
  worst: "BDSJ" }, // 相性✕のタイプコード
```

### 音声を変える

診断には22本の音声(効果音20+BGM2種)が埋め込まれています(Base64のAACデータ)。
`BGM_INDEX` の音声(バジリスクタイム)は質問画面で、`RESULT_BGM_INDEX` の音声は
結果発表と同時に切り替わってループ再生されます。どちらも右下のボタンでミュート可。

効果音は回答のたびに **種類もタイミングもランダム** で鳴ります。
タイミングは「回答ボタンを押した瞬間」「次の質問に行った瞬間」
「次の質問に行ってから2秒後」の3パターンからランダムに選ばれ、
種類はシャッフルバッグ方式で全種を一巡するまで同じ音が重複しません。
`RANDOM_SFX_EXCLUDE` に番号を足すとその音声を抽選から外せます。
固定で鳴るのは `SOUND_EVENTS` の「スタート時」「コピー時」だけです(`null` で無効)。
`SOUND_LABELS` は番号→中身のメモです。

音声を差し替えたい場合は `SND` 配列の `data:audio/aac;base64,...` を
好きな音声のBase64に置き換えてください。

### 画像を変える

各タイプの画像は `<body>` 冒頭の SVG シンボル(`id="pt-タイプコード"`)です。
好きな画像に差し替えたい場合は `<symbol>` の中身を描き替えるか、
`<image href="data:image/..." />` でBase64画像を埋め込んでください。
